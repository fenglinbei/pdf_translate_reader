## 需要纠正的运行解读

1. **两轮最终走 Agent，不等于两轮都发生回落。** 第一轮只能确认 Agent 路径完成；没有保存它的路由日志，不能断言它先进入过长上下文。第二轮已有 `global/high`、进入长上下文及后续 Agent 日志片段，结合最终 `hybrid-retriever-v1` 快照，可确认发生回落。具体异常尚无持久化证据。
2. **带入证据不证明紧邻上一轮的路由。** `findLatestCarryoverEvidence()` 会向前寻找同一文档最近一次非空证据快照，中间即使有长上下文回答也会被跳过。本次两条证据可以直接按 chunk 对应到第一轮；“两轮都回落、系统性失败”的原结论撤回。
3. **`queryPlan.intent=question` 不是路由器输出。** 数据库中两轮都是这个值，它来自规则式查询规划，不能据此否定第二轮日志里的 `global`。
4. **控制器次数没有独立落库。** 两轮分别有 2 / 1 个 `gap_check`，并有非空结束大纲。按当前控制流推断为 3 / 2 次控制器调用，但这不是持久化计数；“gap_check 总是等于调用次数减一”不成立。
