运行 `npm run prepare:qa-production -- output/qa-production` 只生成 SQL 和源文件摘要，不连接数据库：

1. `20260924_qa_document_tools.sql`
2. `20260924_qa_conversation.sql`

4. `20260925_qa_workspace_navigation.sql`
5. `20260925_qa_document_artifacts.sql`

生成包只有一个外层事务，5 秒锁等待、单语句 60 秒期限和事务级发布锁。后半段失败会回滚前面的会话升级；不能留下 scope 已改变、引用能力却未就绪的中间状态。检测到已存在产物表时拒绝重放首发包；之后采用增量迁移，不能重新执行早期较窄的引用约束。

本地 PostgreSQL 兼容引擎已演练完整升级、旧消息/引用保留、私有存储桶、服务端 RPC、重复执行拒绝和末尾失败整批回滚。它不是生产备份恢复演练。生产无需重做 OCR、embedding 或全库产物构建；产物按已有解析文档被使用时准备。

## 切换顺序

1. 核对升配、生产库连接、备份、精确 SHA/摘要及远程 CI，预先安装独立 runtime、版本目录和依赖；服务暂不开放。
2. 现有 HTTPS server 内启用 QA 专用维护 location，保留其余 `/api/` 与静态阅读功能；暂停新问答，确认旧问答已结束。不要直接套用会覆盖双域名的通用整站配置。
3. 在生产库应用整个迁移包；核对旧会话数量、原消息/引用与新权限/RPC。失败整体回滚，恢复旧 QA 入口。
4. 安装独立 QA 单元和正式 `qa.env`，启动 8788；从 loopback 核验身份、鉴权及准备/问答能力。第一次业务冒烟使用明确的临时数据，不操作现有用户文档。
5. 用版本目录和 `app-qa-isolation.conf.example` 切换主 API，设置 `QA_EMBEDDED_ENABLED=false`。这一步需要一次主 API 重启，应在现有翻译完成后执行；不把首次切分描述成零中断。后续 QA 更新只重启独立 QA。
6. 先发布新的哈希资源，再切换前端入口；安装 QA live location，经 `nginx -t` 后 reload。只把 `/api/qa/` 送到 8788，翻译、MathPix 和文库继续 8787。
7. 验证两个正式域名、资源版本、登录、普通问答、文档阅读/引用、旧历史、翻译和文库，再结束维护并记录生产验收。清理本次临时账号和合成数据。

现有手工 `restart.sh` 保留供核对；升级后的发布走这份流程，旧整站脚本需要适配 QA location 后才能再次作为日常发布入口。

## 回退边界

- 首次迁移事务失败：旧数据不变，恢复原 QA 入口，不需要逆向删除字段。
- 新运行协议不稳定：保留新版代码、前端及版本产物能力，把独立 QA runtime 切到 `workspace-tools-v1`；原地升级后的会话和新引用仍可访问。
- 回退到生产旧的文档会话实现：必须先暂停 QA，按备份/`origin_scope` 等字段恢复原会话归属，再切代码。不能只回退二进制，或用整库恢复覆盖上线后新增的文库、翻译和注释数据。新增工作区会话和 v2 引用需要继续保留兼容访问。
- 主 API/静态资源切换失败：使用本轮服务器备份和原 unit/目录恢复；在恢复 QA 路由前先确认所用代码与当前数据库 scope 协议一致。
