## 行为与契约

### 1. 工具参数与引用修复

`read_document(mode=pages)` 明确包含起止页且一次最多 4 页，参数校验在读取前执行。工具说明约定 quote 复制 text，LaTeX 只辅助理解，不用于摘录匹配。

`finish_reading` 检查完整选择列表后再提交引用。失败结果的 `details.failedSelections` 包含从 0 开始的 `selectionIndex`、来源编号、错误码和原因；`matchedSelectionIndexes` 表示已经匹配的选择。模型保留成功项、修正失败项后重交完整列表。文本不存在与上下文不匹配分别反馈，重复原文仍需上下文消歧。匹配规则与最终软件定位的责任不变。

参数修复与引用修复各最多 2 轮，总修复最多 4 轮；第 3 次同类失败结束查阅。原有 8 次规划、12 次工具、每批最多 4 个工具以及无进展上限仍生效。引用输入日志只记录字符长度、来源和摘要哈希，结果日志保存逐项错误；不保存原始摘录参数或私有推理。

### 2. 缓存连续性与过程输出

规划与答案请求保留同一工具定义及 `tool_choice=auto`，累积 assistant/tool 消息不重建。最终以追加消息说明查阅结束，harness 关闭执行权限。若模型仍请求工具，返回逐 call ID 的 `TOOLS_CLOSED`，最多纠正一次；不会重新读取文档。异常半成品答案通过 `answer_reset` 清空，取消、断流和供应商错误不会自动重复生成。

这消除了本轮实测中切换 `tool_choice=none` 引起的前缀断裂，无法保证供应商永远命中缓存。新问题、历史差异、工具返回的新文本与缓存可用性仍影响结果。此项是供应商输入 token 缓存，与运行内相同工具参数复用的 `cacheHit` 是不同指标。

| 新 SSE 事件 | 含义与持久化 |
| --- | --- |
| `commentary` | 模型普通 content 流式过程说明，独立于最终答案；每轮最多展示/保存 1200 字符。运行中状态 running，完成后同一 stepIndex 替换为持久化步骤。 |
| `tool_start` | 工具开始执行的临时状态；结束时使用同一 stepIndex 的已有 tool_call 事件替换并保存。 |
| `answer_reset` | 清除本次暂存答案，处理查阅结束后的违规工具请求。 |

前端按步骤顺序显示过程说明与工具状态，刷新后恢复完成步骤。running 仅是 SSE/UI 临时状态，不新增数据库运行中状态。解析器完整拼接工具增量后才允许执行；`reasoning_content` 仅在运行内按协议续接，不展示、不持久化为过程说明。

### 3. 普通问答与文档问答

同一面板可切换“文档问答 / 普通问答”；未打开文档默认普通问答，两种历史相互独立。普通问答发送 `scope=general` 且不提供 activeDocumentId，直接一次流式模型调用，无文档工具、规划轮、解析产物下载、embedding 或 rerank。可进行日常交流、概念解释、写作、学习安排；没有联网搜索或操作外部系统的能力。

文档问答仍发送 `scope=current` 和 activeDocumentId，省略 scope 的旧客户端仍按 current 校验。文档权限和版本在运行开始检查，解析正文推迟到首次阅读工具时加载；文档模式中的直接交流无需下载正文。需要原文的提问仍要求完成 MathPix 解析，普通问答不会假装已读取当前 PDF。

新增鉴权接口 `GET /api/qa/capabilities` 声明 runtime、generalChat 与可用模型；普通历史通过 `GET /api/qa/threads?scope=general` 获取。会话复用检查用户、scope 和文档身份，禁止将文档会话作为普通会话续问。general 会话数据库约束要求文档为空、参考文档为空；既有 RLS 保证用户隔离且不能给无文档会话插入文档引用。

使用两个临时合成账号、一份两页 PDF 和缓存的解析结果验证。没有生成 embedding、索引或调用 MathPix 服务。以下为真实默认模型、数据库和本地浏览器结果：

短普通问题首轮只有 181 输入 token，缓存命中为 0；追问 268 输入 token，命中 128。输入本身很短且首次使用新提示词时，低命中率不能直接归因于执行器缺陷。缓存比例应同时观察 token 绝对量、调用阶段与模型耗时。

已知限制：提示词要求过程说明跟随提问语言，但最终浏览器样本仍输出英文过程说明，最终答案为中文。当前忠实展示模型普通 content，语言与是否每轮都给说明属于模型遵循度，不能保证；没有额外增加翻译请求。该项已记录为质量限制，不能标为“中文过程说明验收通过”。

本轮没有替代用户对真实长论文的验收；合成样本的高缓存比例不是普遍保证，原两轮失败的具体摘录也不能从旧的长度日志反推。

## 人工验收建议

1. 打开本地测试入口，用现有测试账号对同一论文重新提问，观察过程说明与工具状态是否在答案前交错出现。
2. 追问原先失败的问题；如仍有引用错误，检查本轮日志中的失败 selectionIndex、原因及匹配成功项，不再只有摘录长度。
3. 比较 planning 与 answer_generate 各自和全轮的缓存命中 token，不只看最终请求或界面总费用。
4. 切换普通问答，尝试日常概念/写作问题并继续追问；切回文档，检查历史和引用仍属于原来的论文会话。
