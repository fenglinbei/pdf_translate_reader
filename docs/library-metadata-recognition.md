# 文献库自动识别

## 行为

| 场景 | 触发与结果 |
| --- | --- |
| 首次成功上传到云端 | 数据库插入文献时进入识别队列；本地阅读和上传不等待模型完成 |
| 重新打开、搜索、重复导入同一文件 | 不重复创建任务；重复导入仍沿用原来的文献记录 |
| 已有文献 | 勾选后点击“补全所选文献”，每批最多 100 篇；历史记录不会被升级脚本自动扫描 |
| 单篇补全或重试 | 论文详情中的“重新识别”；已有等待或运行中的任务不会重复入队 |
| AI 开关 | 文献库顶部和设置中共用“AI 辅助补全文献信息”；默认启用，关闭后保留 PDF 提取和文献编号查询 |
| 关闭页面或服务重启 | 队列保存在数据库；后台继续处理，超时的运行租约可恢复 |

开关必须成功保存到云端才显示保存成功，并使用独立数据库字段，避免其他设备或旧版客户端保存普通设置时重新打开 AI。任务会在调用模型前重新读取偏好；关闭对尚未发送的模型请求生效，已发送的请求无法撤回。识别本身不会创建 MathPix 解析或 QA 索引任务，原有阅读器的 MathPix 自动解析设置仍独立生效。

## 识别与覆盖规则

1. 使用现有 PDF.js 读取内置信息和前 3 页文字；XMP 作者数组按顺序保存，旧作者字符串只按分号或换行拆分，保留姓名中的逗号。
2. 从第一页标题区/正文前部提取 DOI 或 arXiv ID。编号有歧义时不查询；返回题名必须与本文题名或首页文字吻合，不能直接采用参考文献编号对应的记录。
3. 查询 [Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) 或 [arXiv](https://info.arxiv.org/help/api/user-manual.html) 的公开元数据。公共查询有超时、体积上限、缓存；arXiv 请求保持至少约 3 秒间隔。
4. 标题、作者、年份仍有不足时，允许执行一次模型提取。模型输入限制为前几页最多 24,000 字符；要求返回原文证据，字段值和证据都必须能在输入中核对。没有依据的字段留空；不发送整份 PDF，不保存模型推理。
5. 扫描件优先复用同一用户、同一文献内容哈希的已完成 OCR 缓存。没有可用文字时显示“需要文字内容”。PDF 下载上限 100 MB，OCR 缓存上限 8 MB。

自动填写空字段和明确记录为文件名占位的标题。对于已有的不同值、来源不明的历史字段、人工修改或人工清空的字段，保留原值并展示建议。仅依靠版面字号推断的标题也进入待确认。

详情页可逐项比较现有值与建议值；默认不勾选。采用建议后该字段标为已保护，并保留来源。直接编辑的字段标为“手工填写”。识别期间发生编辑时，后台根据最新值重新合并，并用版本检查避免覆盖；旧编辑表单保存前也检查版本，冲突时保留草稿并提示重新核对。

列表、详情、快速文献列表及当前阅读页随识别结果刷新。未被手工修改的翻译上下文会接收文献库题名和摘要；手工修改过的翻译上下文保持原值。这里的“已识别”不承诺每项可选字段都有值。

## 运行与发布

需要先执行增量迁移：`supabase/migrations/20260923_library_metadata.sql`。完整 `supabase/schema.sql` 也包含同一段迁移，重复执行不会给历史文献排队。

迁移增加文献上的 `metadata_state`、`metadata_sources`、`metadata_revision`，以及设置上的独立 `library_metadata_ai_enabled` 字段，以及后台队列和确认建议的 RPC。后台 RPC 仅授予 `service_role`，手工确认/编辑 RPC 使用登录身份和文献 RLS。识别结果写回现有 `user_documents` 书目字段，继续使用原搜索索引。

API 服务启动后，每 2.5 秒尝试领取一项任务，每个进程串行处理。数据库锁避免多进程重复领取；租约 5 分钟，正常处理预算 150 秒，模型请求最多 60 秒。任务结果绑定租约标识和字段版本；删除、换租约或过期结果不会写回。

默认使用已接入的 `deepseek-flash`，可通过服务器环境变量 `LIBRARY_METADATA_MODEL` 指定已支持的 QA 型号。提取输出上限 2,200 tokens，不改变正常 QA 的输出预算。需要现有模型密钥及 Supabase service role 配置。

发布顺序：迁移 → API 和前端部署 → 使用授权的实际文献验收。**本次代码实现和隔离验证不代表已执行生产迁移或已部署。** 回退应用时可以保留新增列和 RPC；若需要停止自动识别，应同时停用新插入文献的队列触发器，而不是清空文献数据。

## 验证

- PDF.js 实际解析合成 PDF，验证 XMP 作者数组、标题与页面文字。
- 提取/合并用例覆盖误匹配编号、缺少证据、占位标题、人工清空、旧记录保护、关闭 AI 与失败降级。
- 隔离 PostgreSQL（PGlite）实际执行迁移，验证可重复应用、租约恢复、版本冲突、逐项确认、删除后不回写、跨用户隔离及函数权限。
- 客户端状态用例验证开关云端保存失败、偏好默认值、文献库到翻译上下文的同步和手工上下文保护。
- Chromium 合成界面验证：逐项采纳、AI 开关、后台更新保留草稿、旧表单冲突、批量操作、320px 列表与详情无横向溢出。
- `npm run test:library`、`npm run test:models`、`npm run test:translation`、`npm run test:qa`、`npm run test:mathpix`、`npm run build`。

异常分支的回归使用受控响应。实际 Crossref 与 arXiv 查询分别验证了 `10.1038/nature14539` 和 `1706.03762`，均取回题名、作者和年份。另通过现有 `deepseek-flash` 完成一次真实 API 调用：仅使用虚构论文标题、作者和年份，成功核对题名、两位作者及年份，返回的总用量为 321 tokens。未发送用户真实文献或写入生产数据。真实资料上的识别准确率、上线后的后台吞吐量仍需部署验收。
