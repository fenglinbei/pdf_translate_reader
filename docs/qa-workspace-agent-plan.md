# 工作区问答 Agent 实施契约

日期：2026-09-24。
状态：代码已实现，本地隔离 QA 已部署 `0.4.0-alpha.3`；工程自动验收通过，用户人工验收待进行，生产未部署。

本契约承接已经实现的 [原文引用契约](qa-agent-citation-contract.md) 和 [自动问答入口](qa-conversation-upgrade-2026-09-24.md)。新的会话与工具行为按本文实施；章节定位、关键句所在原文行高亮、已读覆盖和版本校验继续保留。

## 1. 产品目标

问答属于当前登录用户的整个工作区。没有打开论文时也能进入问答；打开、关闭或切换文章只改变阅读焦点，不自动切换会话或清空正在进行的对话。

提供显眼、常驻、带文字的“AI 问答”入口。问答能够直接处理日常问题，也能自主发现用户的文档、选择一篇或多篇查阅，并提供能跳转至对应文档原文的引用。

## 2. 已冻结的产品选择

| 项目 | 已确认行为 |
| --- | --- |
| 入口布局 | 顶部常驻 AI 问答独立页，加阅读器并排侧栏；两处共享同一会话、草稿和生成状态 |
| 旧会话 | 原地升级为工作区会话，保留线程、消息和引用身份，不创建副本 |

旧会话升级保存原始范围和文章来源，以支持历史解释与回退；不复制或删除消息、引用。其余内容根据已讨论方向和现有权限边界实施。

## 3. 工作区、焦点与授权

- 资料范围覆盖当前用户所有未删除且有权限访问的云端文档，发现接口支持查询和分页；归档状态属于筛选信息，不授予额外权限。
- 本地尚未同步的文件不会因提问而自动上传；无法读取的文档明确返回状态。QA 不自动启动付费解析，也不要求 embedding、预切 chunk 或 rerank。
- 当前文章只作为运行环境，不作为线程主键或唯一引用来源。每次提问冻结当时的焦点；提问期间阅读器切换影响下一次提问，避免正在执行的问题无记录地改变指代。
- 模型不能指定用户身份或扩大权限。文档发现、正文读取、引用生成及引用打开均执行服务端的用户隔离和权限校验。
- 当前焦点、可访问集合、模型选中资料、实际已读覆盖分别记录。摘要卡片和目录不视为读过正文。

## 4. 自然执行循环

一次模型请求可以直接返回答案，也可以返回过程说明与工具调用。没有工具调用且正常结束时即可完成；不要求通用 finish_reading，不增加独立分类模型。

工具结果按原生协议回传，继续使用同一有序消息链和稳定工具定义。正常交流目标为 1 次模型请求、0 次工具调用；文档问题按实际查阅需要循环，不固定“先列清单、再搜索、再阅读”的顺序。

保留调用预算、修复预算、取消和超时。模型普通 content 可以流式显示，依据该次请求的结束事件区分过程说明和最终回答；不为这一区分单独调用模型。供应商私有推理续接字段仅在当前运行内按供应商协议处理。

## 5. 工具能力与模型视图

| 能力 | 职责 |
| --- | --- |
| discover_documents | 按需发现授权文档，返回有限候选、已有摘要/摘要来源、当前文章标记及续页信息 |
| document_outline | 获取指定文档的目录与可阅读范围 |
| search_document | 在模型选定的一篇或多篇文档中进行字面搜索 |
| read_document | 按文档、章节、页面或软件签发的来源/续读标识阅读 |
| cite_sources | 选择已读资料及重要原文，由软件映射引用；成功后仍可继续阅读 |

文档发现优先使用已有元数据与缓存摘要；不在提问时逐篇生成摘要。缺失摘要如实返回，截断与分页必须可见。发现结果中的当前文章标记不代表该文章一定匹配了搜索查询。

模型看到正文、来源标识、语义标签、完整性和可操作的错误说明。软件内部保留数据库身份、授权范围、文档版本、已读覆盖、页行坐标及高亮信息。对模型和对界面的输出分别生成。

参数使用明确 JSON Schema 并在服务端校验；删除 finish_reading 的 mode、answerOutline 和结束状态机职责。保留真实输入约束、原文摘录规则、公式保真和明确的续读语义，不以缩短描述为由削弱能力。

## 6. 多文档引用

- 引用标识在本次回答内唯一，不能因不同文章都存在 C1 而冲突。
- 每份来源保留所属文章、版本与实际返回范围；跨文档内容不能拼成单个连续原文位置。
- 模型只选择来源和重要摘录；章节、物理页、原文行和高亮矩形由软件映射。
- 精确引用只允许来自已读内容。原文重复、来源失效、越权、未读缺口等继续有明确处理。
- 点击任意文档的引用可打开对应文章并定位，同时保留问答会话与消息。旧引用始终绑定原来的文档版本，不跟随当前焦点重解释。
- 原文定位一致性不等同于语义证明；回答质量通过真实问题和有证据的评测核验。

## 7. 上下文、缓存和可审阅记录

固定提示词保留问答原则、资料使用边界、引用要求、语言与公式格式。用户提问保持原文，历史使用真实角色，动态运行环境独立且标记来源。可信模型身份来自配置。

同轮工具 schema 和消息前缀保持稳定；动态环境发生变化时追加。衡量实际调用数、输入/输出量、缓存命中绝对量、首字时间、总时长与质量，不单独追求命中率百分比。

保存可审阅的系统提示词、工具 schema、公开消息、工具原始参数、模型可见结果、请求选项和细分耗时。鉴权头、凭据不进入记录；未持久化的供应商私有续接字段明确标注缺失，不宣称可以逐字重放整个请求。

同一个工具 callId 在 UI 中是一张更新状态的卡片；底层执行和观察事件不重复呈现为两次工作。

## 8. 兼容与发布

新路径使用独立的工作区 runtime 和 prompt 版本，本轮 QA 发布版本为 `0.4.0-alpha.3`；保留旧执行路径以便回退。数据库采用增量迁移，不删除原问答历史和引用。旧会话按第 2 节原地升级。

只切换本地隔离 QA 服务及测试前端，按既有流程先备份、运行迁移与预检、部署后核验健康和真实场景。主阅读、翻译、文库、解析服务和生产入口不随本轮 QA 升级切换。

开发完成运行相应单元/数据库测试、全量 CI、浏览器流程与隔离账号真实模型验收。代码提交和推送沿用 qa-agent 分支的既有授权；发布状态分开记录代码实现、本地部署、人工验收和生产部署。

## 9. 验收清单

1. 未打开文档时能看见并打开 AI 问答，发送普通问题。
2. 打开论文后问模型身份或日常问题：1 次模型请求、0 工具，正常回答。
3. 问当前文章的实现：自主查阅，公式正常，引用定位章节或关键句所在行。
4. 当前打开 A，提问明确针对 B：能发现并查阅 B。
5. 比较 A 与 B：两篇的引用各自打开正确文档，问答保持不变。
6. 普通 → 当前文章 → 多文档 → 普通连续对话：会话与历史连续。
7. 提问期间切换焦点：本轮指代固定，下一轮使用新焦点。
8. 文库分页、摘要缺失、未解析文档：如实反馈，不自动解析、不伪造全文阅读。
9. 删除/撤权/来源变化/取消/模型错误：保持权限与来源边界，有限恢复或明确终止。
10. 旧历史与引用按最终兼容方案可用；未因升级丢失。
11. 工具步骤无重复卡片，过程文字自然穿插，逐轮公开 prompt 和工具交互可审阅。

## 10. 实现与运维接口

- 代码路径：`server/qa/workspace/`；复用原文视图与映射，不依赖 chunk、embedding 或 rerank。
- 用户只传自然问题；普通交流也使用同一组稳定工具定义，但无需实际调用。
- 单次上限：12 轮模型、24 次工具、每批 4 个调用、4 次可修复工具错误；正文返回累计最多 96,000 字符。
- 模型视图：文档 `D1` / `current`，已读来源 `R1`，最终引用 `C1`；编号仅在当前提问内有效。
- 元数据发现每页 10 条，以标题、文件名、已有摘要的字面包含筛选；不生成新摘要。元数据缺失或词形不同可能漏匹配，模型可更换关键词。
- 已登录用户可通过 `GET /api/qa/messages/{messageId}/trace` 审阅自己未删除消息的公开逐轮记录；记录含文档内容，不应公开上传。
- 迁移新增 `origin_scope`、`origin_user_document_id`、`workspace_upgraded_at`。原引用无需重建。
- 回退旧 runtime 前需暂停 QA，按备份/来源字段恢复升级前线程的 scope 和 active_user_document_id；升级后新建工作区会话保留，新旧 runtime 不能同时写入同一迁移中的线程。仅切 runtime 无法恢复旧文档会话列表。

工程验证：全量 363 项测试、数据库权限测试及构建已通过；真实 DeepSeek V4.1 Flash、公开运行记录和浏览器验证结果见下节。

仅使用隔离测试项目和临时合成账号/文档；运行没有 QA chunk、embedding 或 rerank。下面是同一旧会话原地升级后的真实模型调用，计时包括数据库持久化和网络，不能作为固定延迟承诺。

| 场景 | 模型请求 | 工具调用 | 引用 | 总耗时 | 输入缓存命中 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 模型身份（包含错误历史） | 1 | 0 | 0 | 7.3 秒 | 0 / 2482 tokens |
| 当前文档原理与公式 | 3 | 2 | 1 | 16.5 秒 | 7680 / 8431 tokens |

所有成功场景均无工具错误，公开请求和响应记录完整。新提示词第一次请求为冷缓存；命中比例受历史与供应商缓存状态影响，不能替代总请求数和输入量。

数据库验证了迁移幂等、旧 ID/原消息/原引用保留、跨用户焦点与运行记录访问拒绝。真实历史列表分页返回 30 + 3 条，不重复。来源变更测试触发 `DOCUMENT_VERSION_CHANGED` 并停止取证：测试 PDF 的缺失缓存补全导致版本变化，稳定后重新查阅通过，没有放宽版本校验。

浏览器验证了显眼入口、独立页和侧栏仅一个会话实例、跨布局保留草稿、390 像素窄屏与桌面输入框可见、LaTeX 公式显示，以及跨文档打开后的原文行高亮。生成中由 Alpha 切换至 Beta，本轮仍引用 Alpha，界面保持 Beta，未中断会话；下一轮普通问题使用 Beta 环境，零工具直接回答。

真实验收曾发现两处问题并已修复：失败助手回复被过滤后留下未闭合的旧提问；长对话导致输入框超出视口。前者保留失败占位并明确只回应最新请求，后者修正父容器和消息区的高度分配。

权限和版本校验保证来源归属与位置一致，不证明模型每个论断均被引用语义支持；用户人工验收仍需检查回答质量。词内精确高亮、视觉问答和自动付费解析不在本轮范围。
