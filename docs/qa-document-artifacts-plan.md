# 版本化文档与直接引用：冻结方案和分步交付

日期：2026-09-25。用户已确认总体设计、客户端/服务端职责，并授权分步实施。

本文是新的增量契约。旧 `workspace-tools-v1`、`citation-locator-v1` 在新路径验收前继续服务；本文中“冻结”不代表已经部署。

## 1. 冻结边界

- 模型决定读哪些资料、哪些资料重要。软件维护正文、阅读覆盖、原文位置；不要求模型计算页行坐标或重新抄写原文才能引用。
- 逻辑正文与物理版面分别保存，用版本化 SourceMap 连接。自然段、章节、表格有节点身份，不建立 embedding 或固定 token 检索 chunk。
- 客户端 Web Worker 优先完成正文结构和原文映射构建；产物保存到私有对象存储并跨设备复用。
- 服务端确认用户权限、源版本和产物一致性；运行 Agent、签发已读句柄、执行有预算的工具、记录用量及保存答案。
- 浏览器渲染 Markdown/公式/引用，并按保存的原文位置跳页、高亮。源版本一致且映射已缓存时，点击不再请求服务器重新找原文。
- 阅读时登记候选引用，答案首次使用时才展示来源；普通段落、表格引用不强制调用 `cite_sources`。
- 流式引用可显示与回答已持久化是独立状态。内部可恢复的映射处理不展示“正在校准引用位置”。
- 保留章节定位与关键句所在行高亮，逐字高亮不在范围。普通交流不需要读取文档。
- 不自动上传本地文档、不自动触发付费 OCR，不修改阅读器、翻译、文库的生产服务。

## 3. 客户端与服务端职责

| 能力 | 执行者 | 复用与限制 |
| --- | --- | --- |
| 获取已授权的 OCR 结果 | 现有 MathPix 流程 | 不增加 OCR 次数 |
| 规范正文、结构、SourceMap 候选 | 客户端 Worker | 每版本一次，分批、可取消、可恢复 |
| 发布校验 | 服务端受限任务 | 一次性校验，不能仅凭哈希宣称位置正确 |
| 产物与 PDF 传输 | 浏览器/QA 直读私有对象存储 | 数据权限有效，正文和定位数据按需读取 |
| 发现、读取、字面查找 | QA 工具 | 限定文档、输入、扫描和返回预算 |
| 模型循环与已读登记 | QA 服务 | 用户/run 隔离，源版本固定 |
| 引用语法/显示、跳转、高亮 | 浏览器 | 不重新检索；未缓存版本仍需加载 |
| 引用成员校验、最终保存 | QA 服务 | 按涉及文档去重，消息/引用事务保存 |

客户端产物在发布前都是候选。发布校验必须依托受信源记录检查权限、版本、正文派生、范围和映射一致性；结构校验、哈希或客户端自报“已验证”不能代替这一过程。

## 4. 产物与身份

### 4.1 冻结的基础格式

`document-artifact-v1` 是新的产物格式，和旧 `document-view-v1` / `citation-locator-v1` 独立编号。

- `revision` 由 PDF 内容哈希、MMD 哈希、版面哈希、构建器与映射规则版本计算；不使用访问时间或数据库更新时间作为内容身份。
- `nodes` 保存逻辑正文、类型、父节点与在正文源中的范围。节点 ID 在同版本中确定，重复正文不同出现位置有不同 ID。
- `regions` 保存物理页、原始行、原始文字及可选的归一化矩形，缺坐标不能借用邻行。
- `mappings` 把节点的 UTF-16 半开区间映射到一个或多个原文区域及其原始文字区间。允许未映射区间，但不能伪装成完整精确定位。
- 物理高亮区域可以比实际阅读范围大；只有签发句柄的逻辑正文区间计为已读。
- 对章节节点，标题身份属于导航；引用整章需要覆盖其实际正文。不能仅签发标题句柄就声称读过整章。

传输与存储阶段将这些对象分为 manifest、reading parts、location parts。拆文件不改变节点或引用身份。基础模块中的完整产物仅用于构建和验证，不意味着问答进程每次加载完整产物。

### 4.2 本轮句柄

`read-reference-v1` 的内部身份包括 user、run、document、revision、node 和实际正文范围。模型看到 `R1` 等短句柄、正文及章节标签。用户显示编号按答案首次引用产生，不复用数据库主键作为模型标识。

读到相同范围时保持相同句柄，但再次返回的文字仍计入资料预算。单批读取原子登记；任一项非法或超出预算，不签发该批其他句柄。历史回答中的编号不能直接用于新 run。

节点及映射在进入已读登记前被复制、校验并冻结，登记后不能被外部对象修改。此处只是运行内身份和范围验证；权限/撤权仍由工具入口与最终保存边界检查。

## 6. 回归与性能验收

- 阅读正文保留正常词形，物理跨行仍可定位；不能将全局去空格/模糊相似度当作精确匹配。
- 同位置的整表与子行表达不会重复成为多个来源；不同位置相同文字仍独立。
- 实际章节结构正确，表格内容和参考文献年份不变成章节。
- 只读部分段落/表格，只能引用已读范围；目录/摘要不算正文。
- 多文档、同名节点、重解析、换用户、旧 run 引用均不串源。
- 不存在坐标时降级为有根据的页码或不可定位；不猜页码。
- 发布后重复提问不重新构建整篇正文；缓存有估算字节与条目上限。
- 流式分片、引用重写、取消、慢连接、保存失败均有明确状态；不依赖保存后的引用 UUID 才渲染。
- 问答并发、用户公平性、准备并发和模型额度分别控制；多进程前不能把内存计数称为全局限额。
- 保留公开逐轮 prompt 调试能力，后续以不可变快照/增量减少重复数据；不删除用量及必要终态记录。

## 7. 交付隔离

从已经验证的 QA 工作区 UI 基线建立独立工作树。准备阶段代码不接入运行中的 UI/QA，不修改主工作树。私有 PDF、真实运行明细及凭据不提交。

新 runtime、存储格式、SSE 事件采用显式版本/开关，默认保留旧路径。数据库只做兼容增量迁移；代码回退不删除历史数据。测试前端、QA API 和测试库分别验证，生产不随本任务部署。

代码实现、本地验证、远程 CI、隔离部署、人工验收分别记录，不能互相替代。

## 8. S1 交付记录

开发版本：应用 `0.3.0-alpha.1` / QA `0.5.0-alpha.1`。

- `shared/qaDocumentArtifact.mjs`：浏览器/Node 共享契约，内容版本与出现位置身份、UTF-16 范围、结构/直接映射校验、不可变快照、行/块/页级定位。
- `server/qa/documentArtifacts/readReferences.mjs`：服务端登记真正返回的正文；原子批次、预算、固定文档快照、用户/run 隔离；标题不授予整章阅读。
- `server/qa/documentArtifacts/partCache.mjs`：按用户、文档版本和 part 隔离的 LRU；限制估算驻留字节和条目数，只接受不可变数据，不缓存权限结论。它是缓存原语，尚未接入真实加载器。
- `npm run demo:qa-artifacts`：在合成映射上观察 `moderate` 到两行原文、部分句子到另一页的对应，无模型/数据库调用。

验证：新增 18 项行为测试；完整本地 CI 共 385 项测试及 TypeScript/构建通过。Playwright 驱动真实 Chromium Worker 完成 8 项合成检查，包括 Web Crypto 版本计算、跨行定位、部分阅读、块级表格、用户隔离和输入防篡改。

测试中的映射是明确标注的合成预构建映射；本阶段没有实现真实 MMD 自动对齐、同表父子表达去重、产物发布授权或实际共享加载。不能据此宣称线上断词问题已修复、真实引用已切换、缓存已提速或客户端构建任务已上线。发布校验仍须检查候选与授权解析产物的关系，结构校验不证明 OCR 内容或任意结构转换正确。

S1 不增加迁移、不启动后台服务、不改变并发、不清理任何版本，也未部署到测试页或生产。D1/D2 仍等待用户答复。远端提交与 CI 结果在实际推送后单独记录。
