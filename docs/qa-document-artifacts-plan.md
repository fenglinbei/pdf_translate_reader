# 版本化文档与直接引用：冻结方案和分步交付

日期：2026-09-25。用户已确认总体设计、客户端/服务端职责，并授权分步实施。

本文是新的增量契约。旧 `workspace-tools-v1`、`citation-locator-v1` 在新路径验收前继续服务；本文中“冻结”不代表已经部署。

## 1. 冻结边界

- 模型决定读哪些资料、哪些资料重要。软件维护正文、阅读覆盖、原文位置；不要求模型计算页行坐标或重新抄写原文才能引用。
- 逻辑正文与物理版面分别保存，用版本化 SourceMap 连接。自然段、章节、表格有节点身份，不建立 embedding 或固定 token 检索 chunk。
- 客户端 Web Worker 优先完成正文结构和原文映射构建；产物保存到私有对象存储并跨设备复用。
- 服务端确认用户权限、源版本和产物一致性；运行 Agent、签发已读句柄、执行有预算的工具、记录用量及保存答案。
- 浏览器渲染 Markdown/公式/引用，并按保存的原文位置跳页、高亮。源版本一致且映射已缓存时，点击不再请求服务器重新找原文。
- 阅读时登记候选引用，答案首次使用时才展示来源；普通段落、表格引用不强制调用 `cite_sources`。
- 流式引用可显示与回答已持久化是独立状态。内部可恢复的映射处理不展示“正在校准引用位置”。
- 保留章节定位与关键句所在行高亮，逐字高亮不在范围。普通交流不需要读取文档。
- 不自动上传本地文档、不自动触发付费 OCR，不修改阅读器、翻译、文库的生产服务。

## 3. 客户端与服务端职责

| 能力 | 执行者 | 复用与限制 |

| 获取已授权的 OCR 结果 | 现有 MathPix 流程 | 不增加 OCR 次数 |
| 规范正文、结构、SourceMap 候选 | 客户端 Worker | 每版本一次，分批、可取消、可恢复 |

## 4. 产物与身份

### 4.1 冻结的基础格式

`document-artifact-v1` 是新的产物格式，和旧 `document-view-v1` / `citation-locator-v1` 独立编号。

- `revision` 由 PDF 内容哈希、MMD 哈希、版面哈希、构建器与映射规则版本计算；不使用访问时间或数据库更新时间作为内容身份。
- `nodes` 保存逻辑正文、类型、父节点与在正文源中的范围。节点 ID 在同版本中确定，重复正文不同出现位置有不同 ID。
- `regions` 保存物理页、原始行、原始文字及可选的归一化矩形，缺坐标不能借用邻行。
- `mappings` 把节点的 UTF-16 半开区间映射到一个或多个原文区域及其原始文字区间。允许未映射区间，但不能伪装成完整精确定位。
- 物理高亮区域可以比实际阅读范围大；只有签发句柄的逻辑正文区间计为已读。
- 对章节节点，标题身份属于导航；引用整章需要覆盖其实际正文。不能仅签发标题句柄就声称读过整章。

传输与存储阶段将这些对象分为 manifest、reading parts、location parts。拆文件不改变节点或引用身份。基础模块中的完整产物仅用于构建和验证，不意味着问答进程每次加载完整产物。

### 4.2 本轮句柄

`read-reference-v1` 的内部身份包括 user、run、document、revision、node 和实际正文范围。模型看到 `R1` 等短句柄、正文及章节标签。用户显示编号按答案首次引用产生，不复用数据库主键作为模型标识。

读到相同范围时保持相同句柄，但再次返回的文字仍计入资料预算。单批读取原子登记；任一项非法或超出预算，不签发该批其他句柄。历史回答中的编号不能直接用于新 run。

节点及映射在进入已读登记前被复制、校验并冻结，登记后不能被外部对象修改。此处只是运行内身份和范围验证；权限/撤权仍由工具入口与最终保存边界检查。

## 6. 回归与性能验收

- 阅读正文保留正常词形，物理跨行仍可定位；不能将全局去空格/模糊相似度当作精确匹配。
- 同位置的整表与子行表达不会重复成为多个来源；不同位置相同文字仍独立。
- 实际章节结构正确，表格内容和参考文献年份不变成章节。
- 只读部分段落/表格，只能引用已读范围；目录/摘要不算正文。
- 多文档、同名节点、重解析、换用户、旧 run 引用均不串源。
- 不存在坐标时降级为有根据的页码或不可定位；不猜页码。
- 发布后重复提问不重新构建整篇正文；缓存有估算字节与条目上限。
- 流式分片、引用重写、取消、慢连接、保存失败均有明确状态；不依赖保存后的引用 UUID 才渲染。
- 问答并发、用户公平性、准备并发和模型额度分别控制；多进程前不能把内存计数称为全局限额。
- 保留公开逐轮 prompt 调试能力，后续以不可变快照/增量减少重复数据；不删除用量及必要终态记录。

## 9. S2 交付记录

## 10. S3 交付记录

开发版本：应用 `0.3.0-alpha.3` / QA `0.5.0-alpha.3`。

- 私有 `qa-document-artifacts` 存储和仅服务端可写的发布记录。用户只能上传其当前构建租约的候选，不能替换已发布版本。源文件路径需同时匹配用户、PDF 哈希及解析配置，服务权限不会下载用户伪造的跨用户路径。
- 服务端 Worker 根据授权 MMD/版面独立重建并比较候选，校验和文件上传完成后才事务发布。每次尝试独立目录，失败清理不触碰已经提交的版本；数据库状态不明时保留文件供后续核对。
- 准备任务每进程 1 个运行、2 个排队；数据库租约限制每用户 1 个活动准备。Worker 256 MiB、60 秒计算期限，完整任务 120 秒；浏览器可取消构建，已进入发布验证的共享任务可继续完成。它们不是多节点总 CPU 限额。
- 正文和位置独立分片，相邻小段合并传输文件，节点身份和实际已读范围不变。真实 9 页样本的 111 个节点合为 2 个正文文件和 5 个定位文件；manifest 约 40 KiB，分片约 294 KiB。单次样本不是容量基准。
- 问答读取器按需加载、验证摘要并使用 32 MiB / 256 项估算 LRU；同用户同版本请求合并。正文批次只在批次前后检查权限，缓存不会保存授权结论。位置文件仅定位时加载。
- 已发布版本留存 PDF、MMD 和版面文件。相同内容重解析复用原版本；每用户已发布产物限 1 GiB，达到限制报错，不自动删除历史。主动删除文档后 API、数据库行与新的存储鉴权请求撤权。客户端私有下载使用独立访问参数并禁用 HTTP 缓存，内容复用由有界应用缓存管理；已经下载到设备的字节无法远程收回。
- 仅开关启用的隔离前端执行准备；第二设备直接复用已发布产物，无 Worker 构建和准备请求。没有新增付费 OCR 或模型调用。

验证：16 项新增契约、Worker、实际 SQL 测试（包括 10 段批次只检查两次权限）；完整 CI 共 409 项通过。隔离 QA 数据库迁移前已备份。真实 Chrome 完成客户端准备、候选发布和第二设备复用；两个临时用户验证租约竞争、外用户不可读、暖缓存命中及 `moderate` 两行定位。同内容重解析和删除撤权另用临时夹具核验；测试发现旧下载 URL 可能命中对象存储 HTTP 缓存，实际客户端已改为新的鉴权下载，不能把缓存下载当作再次授权。测试文件与凭据仅在忽略目录。

本阶段只在额外的本地隔离端口启用准备 API；现有测试页、主阅读器和旧问答执行循环仍照常运行。S4 接入直接引用，S5 完成事务保存、10 用户负载和最终测试页部署后再交付人工验收。

- 新版来源 `document_artifact` / `citation-locator-v2` 保存修订、节点、实际已读区间和内容摘要。正文读取不加载坐标；只有首次使用的 R 句柄才转为 C 编号并展示，单回答最多 32 项。
- 流式解析器缓冲分片标签，来源元数据先于标签输出；代码与数学内容不作为引用语法。无效句柄最多一次修正，重置清空这一尝试的正文和来源。Markdown 语法树处理粗体、标题、列表和表格中的引用，不必等数据库 UUID。
- 浏览器提前加载并验证 manifest 与相关分片，正文/位置最多 4 路下载，预取队列最多 32 项/同时 2 项；缓存按用户/文档/版本隔离，估算 24 MiB、128 项。内容已缓存且当前 PDF 哈希一致时，点击只在本地跳页高亮；不再调用旧 readiness 接口。未定位来源没有伪造页码。
- 跨文章引用打开对应文章；PDF 已替换时使用保留版本的临时只读阅读器，不改当前文库、注释、阅读位置或 MathPix 缓存。旧 `citation-locator-v1` 历史仍走兼容逻辑。
- 新引用使用 `qa_commit_artifact_answer` 将答案与来源一起保存，按文档去重检查所有权和存活状态，并检查保留版本身份。失败整批回滚；相同提交可幂等重试。保存失败在界面保留失败状态；最终日志失败不会把已保存答案改成失败。

新增 13 项行为测试覆盖句柄范围、章节不授予阅读、流式分片、正文/数学区分、普通问答、事务回滚/幂等、保存失败和格式嵌套引用。完整本地 CI 与构建通过。隔离 QA 数据库在一致性快照备份后应用兼容迁移；通用 pg_dump 在本轮连接上超时，未把不完整备份当作成功。

真实 Chrome + 临时用户 + 模拟模型已验证工具读取、答案流式引用（含粗体）、LaTeX 与真实数据库保存，无付费模型/OCR 调用。后续 S5 验证 10 用户及部署；目前的模拟结果不代表真实模型的引用选择准确率或生产容量。

## 12. S5 交付记录

开发版本：应用 `0.3.0-alpha.5` / QA `0.5.0-alpha.5`。流程与职责见 [实现说明](qa-document-artifacts-flow.md)，实际部署状态见 [交付记录](qa-document-artifacts-acceptance.md)。

- 新运行路径默认每进程 2 个执行、8 个等待；按通过鉴权的到达顺序入队，同一用户含排队在内仅一个活动请求。队列满立即拒绝，等待 120 秒超时，断开等待连接即移除。旧运行路径默认没有等待队列。多进程部署仍需共享调度，不能把此配置当作跨进程限流。
- SSE 尊重写入背压，维持来源先于引用标签的顺序；总缓冲最多 1 MiB，连续 30 秒不能继续发送即中止上游并清理连接。
- 小段落检索最多 256 个节点一批，权限检查在批次前后执行，不对每个段落远程请求。测试中的 90 段扫描仅两次授权；内部扫描不签发已读句柄。最终检查按文档去重为一次查询，事务保存仍再次锁定并校验权限。
- 原生工具、已读账本、内容缓存、准备任务、模型预算与传输队列分别设限；不把正文缓存命中当作模型供应商缓存命中。

D2：10 个临时用户同时提交普通问答，真实 QA 鉴权与数据库、模拟模型。10 个 HTTP 200、10 条成功消息，峰值 2 个运行/8 个等待，最后全部名额释放；含结果核验约 28.1 秒，单请求约 5.1–26.7 秒，最大排队 21.4 秒。进程 CPU 约 470 ms，RSS 从 98.9 MiB 到峰值 112.6 MiB。模拟输出节奏、网络与数据库时延都包含在内，不是长论文容量或真实供应商吞吐量结论。付费模型与 OCR 调用均为 0。

浏览器补充验收：流式粗体引用可点击且没有裸标签闪现；来源缓存后点击到两行高亮样本为 26 ms、没有新定位请求。未预取的冷缓存仍受网络影响，不能据此承诺所有点击瞬时完成。替换合成 PDF 后，旧回答打开引用时的只读版本、正确高亮，并能返回当前文章。

保留旧格式历史与兼容增量迁移；新的 `document_artifact` 来源需要支持 v2 的前端，回退时不要将其解释成旧的块引用。测试仅替换 5175/8791，主服务、核心 API 与旧测试入口保持不变。真实模型选择的相关性与用户实际论文体验待人工验收。
