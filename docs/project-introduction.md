# PDF Translate Reader 项目介绍

> 一款面向科研、学习与专业阅读场景的智能文献工作台，把文献管理、PDF 精读、实时翻译、自由翻译与原文问答整合在同一条工作流中。

## 项目定位

PDF Translate Reader 不只是一个 PDF 阅读器，也不只是一个翻译工具。

它希望解决的是外文文献阅读中长期存在的割裂问题：论文散落在不同文件夹里，阅读时需要反复切换翻译工具，重要内容难以沉淀，读完之后又很难快速找回，而通用 AI 对论文的回答常常缺少可靠的原文依据。

因此，项目围绕一篇文献从“收集”到“理解”的全过程展开：

**导入与整理文献 → 在原文中即时翻译 → 记录重点与阅读进度 → 通过 Agent 深入提问 → 在任意设备继续阅读。**

所有核心能力都围绕当前文献协同工作，不需要在阅读器、翻译网站、笔记软件和通用聊天工具之间来回切换。

## 核心特色

### 1. 实时划词翻译：翻译发生在阅读现场

阅读外文论文时，最影响专注的往往不是某个生词，而是为了理解一句话不断复制、切换窗口、粘贴和寻找上下文。

PDF Translate Reader 将翻译直接放在 PDF 页面上。选中文本后，译文以流式方式实时生成，并显示在贴近原文的浮动卡片中，让视线和思路都留在当前页面。

它并非简单地把选中文字单独发送给模型，而是会结合句子边界、相邻语句和可选的论文上下文进行翻译。对于公式、复杂排版或原生文本层质量较差的论文，还可以使用 MathPix 解析结果作为更可靠的文本来源。

划词翻译支持：

- 连续拖选与跨区域选取，兼顾常规段落和复杂 PDF 排版；
- 基于当前句及前后文的上下文翻译，减少指代和术语误判；
- DeepSeek、GLM、Kimi 等多种模型选择；
- 论文级翻译风格与术语设置，让同一篇论文中的表达保持一致；
- 译文卡片拖动、缩放、折叠、固定与重新翻译；
- 将重点内容保存为高亮、批注或固定翻译卡片；
- 翻译结果缓存，重复查看时无需再次请求模型。

这套交互的目标很简单：**从“把原文送去翻译”变成“在原文上直接理解”。**

### 2. 文献管理：从文件列表升级为研究工作台

当论文数量变多后，单层文件列表很快就会失效。PDF Translate Reader 采用“一个文献实体，多种组织视角”的管理方式：同一篇论文可以同时属于多个专题合集，也可以拥有多个跨项目标签，而不需要复制 PDF 文件。

文献库提供：

- 题名、作者、年份、期刊或会议、DOI、arXiv ID、摘要等元数据管理；
- 可分层的合集与可复用的标签；
- 收件箱、待读、在读、已读等阅读状态；
- 星标、未分类、最近阅读和归档等系统视图；
- 按题名、作者、DOI、摘要、合集和标签搜索；
- 按导入时间、最近打开、最近整理或题名字母顺序排序；
- 批量修改阅读状态、星标、归档、合集和标签；
- 基于文件内容哈希的精确去重，避免重复导入同一份 PDF；
- 归档而不删除，保留原文、阅读位置、翻译与问答资产。

文献管理和阅读器不是两个割裂的模块。从文献库打开论文后，会直接回到原有阅读界面，并恢复这篇论文对应的阅读状态与研究记录。

### 3. DeepL-like 自由翻译：为学术内容设计的双栏翻译台

除了在 PDF 中划词，项目还提供独立的自由翻译工作台。它采用类似 DeepL 的源文—译文双栏结构，可直接输入或粘贴任意文本，适合翻译摘要、审稿意见、邮件、研究笔记以及暂未导入系统的材料。

自由翻译不仅追求操作直观，也针对学术内容增加了更深入的控制：

- 自动识别源语言、手动选择语言与一键互换；
- 流式输出，可随时停止并保留已经生成的内容；
- 可调整源文与译文区域比例，并支持宽屏、最大化和自定义尺寸；
- 可选择 DeepSeek、GLM、Kimi 等不同模型；
- 可临时指定术语对照，统一专业名词译法；
- 可选择学术忠实、学术流畅、简明直译、发表润色、读者友好等预设风格，也可以输入自定义翻译要求；
- 阅读论文时，可按需带入当前论文的标题和摘要作为背景；
- 支持模型思考模式与思考强度选择，并展示简洁的处理进度；
- 对 Markdown、表格、列表、脚注及 LaTeX 数学公式进行结构化渲染；
- 保留原始译文复制能力，便于继续编辑或用于其他写作工具。

它既保留了通用翻译工具“粘贴即可使用”的低门槛，又能利用论文上下文、术语和风格约束，提供更适合科研写作与专业交流的译文。

### 4. 文献阅读 Agent：回答问题，也给出回到原文的路径

PDF Translate Reader 内置面向当前论文的阅读 Agent。它不是只把整篇论文塞进一次对话，而是先对论文建立可检索索引，再围绕问题执行受控的多步检索与回答。

Agent 会根据问题制定检索计划，在当前论文中搜索证据、打开相关文本块、检查信息缺口并组织回答。检索过程结合全文匹配、向量语义召回和重排序，在问题表述与论文原文用词不完全一致时，仍能找到更相关的段落。

阅读 Agent 的主要能力包括：

- 针对当前论文持续追问，并结合近期对话理解上下文；
- 可调节快速、标准或深入等推理强度；
- 展示计划、工具调用、证据观察、缺口检查和回答提纲等执行阶段；
- 回答附带页码、原文片段与引用验证状态；
- 点击引用即可跳回 PDF 对应页面，核对上下文；
- 保存问答会话、消息、引用和 Agent 执行记录；
- 当复杂检索不可用时自动降级，尽可能保持问答可用。

MathPix 解析和问答索引均由用户决定何时触发，避免仅仅因为打开或同步一篇论文就自动产生额外解析与索引成本。

这项功能的核心不是让 AI “替用户读完论文”，而是帮助用户更快地定位证据、梳理论证，并始终保留从结论返回原文的能力。

### 5. 完整的云端同步：换一台设备，继续同一场阅读

项目将云端同步作为基础能力，而不是后期附加功能。用户登录后，文献本身及其阅读资产会关联到同一账户，并在不同设备之间恢复。

当前云端同步覆盖完整的文献阅读主流程：

- PDF 原文件与文献基础信息；
- 题名、作者、摘要等元数据，以及合集、标签、阅读状态、星标和归档状态；
- 最后阅读页、页面滚动位置和缩放比例；
- 划词翻译缓存、论文上下文和论文级翻译风格；
- 高亮、批注与固定翻译卡片；
- MathPix 解析状态及已完成的文本缓存；
- 问答索引、论文分块与参考文献信息；
- Agent 对话、消息、引用、检索步骤与工具调用记录；
- 用户的阅读和翻译设置。

本地 IndexedDB 缓存用于加快打开速度并增强网络波动时的可用性，云端则负责跨设备恢复和长期保存。PDF 与用户数据存放在私有存储和受行级安全策略保护的数据表中，不同账户之间相互隔离。

这里的“完整”特指与文献相关的核心阅读资产。自由翻译中的临时草稿和最近翻译历史目前仍只保存在当前浏览器中，不会自动上传到云端。

## 一条连续的文献工作流

在 PDF Translate Reader 中，一篇论文不再只是一个静态文件：

1. 导入 PDF，系统完成云端保存与精确去重。
2. 在收件箱中补充元数据，加入合集和标签，并设定阅读状态。
3. 打开论文，系统恢复上次阅读位置。
4. 阅读过程中直接划词翻译，将重要译文固定、收藏或转为批注。
5. 遇到复杂内容时，将选文送入自由翻译台，加入术语、风格和论文背景。
6. 需要理解方法、实验或结论时，向阅读 Agent 提问并沿引用返回原文。
7. 关闭页面后，在另一台设备上继续同一篇论文、同一处位置和同一组研究记录。

## 项目特点总结

PDF Translate Reader 的差异化并不来自某一个孤立的 AI 功能，而来自这些能力在同一篇文献上的协作：

- **阅读不中断**：翻译和批注都发生在 PDF 原文之上；
- **翻译有上下文**：句子、论文背景、术语和风格共同参与翻译；
- **管理面向研究过程**：合集、标签和阅读状态比单纯文件夹更灵活；
- **问答可以核验**：Agent 的回答附带证据、页码和原文入口；
- **研究资产可延续**：文献、进度、翻译、批注和问答随账户跨设备恢复；
- **成本由用户控制**：MathPix 解析和问答索引保留显式触发权。

它希望成为的，是一个真正围绕“读懂一篇论文”而设计的长期工作台。
