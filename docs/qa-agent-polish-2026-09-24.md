## 公式为什么没有使用 LaTeX

发现两处缺口：

- 原生执行器的 system 提示词规定了工具与引用行为，没有规定公式输出格式。
- MathPix 缓存同时保存 `text` 和部分行的 `latex`，原文视图保留了后者，但工具只返回 `text`。模型读不到已经存在的格式信息。

修复后，阅读和搜索工具返回完整已读行的 `latexLines: [{ text, latex }]`。补充表达及其对应文本计入每次资料与整轮预算；超过预算或只读到部分行时，省略该表达并返回 `latexOmitted`，不泄漏未读的行余文。

`qa-document-tools-v2` 提示词要求数学变量使用 `$...$`、独立公式两侧的 `$$` 各自独占一行，公式不用代码块包裹，引用编号放在公式外；解释符号，区分论文原式与自行推导。

引用仍从规范 `text` 中摘录，LaTeX 不替换该文本、偏移或行坐标；来源视图版本和历史引用身份不变。前端已有 remark-math / KaTeX 渲染能力，本次修复补齐输入和输出约定。

## 点击等待来自哪里

原链路为：点击 → 获取登录会话 → QA API → Supabase 鉴权 → 查询用户文档 → 查询 MathPix 解析版本 → 比较来源版本 → 设置定位请求 → PDF 平滑滚动及高亮。

其中后三次云端访问串行执行。对同一临时文档测量三次：

| 采样 | 鉴权 | 文档查询 | 解析查询 | 整段校验 |
| --- | --- | --- | --- | --- |
| 1 | 652 ms | 2,567 ms | 292 ms | 3,520 ms |
| 2 | 411 ms | 266 ms | 280 ms | 960 ms |
| 3 | 370 ms | 260 ms | 284 ms | 915 ms |

首次采样中的文档查询较慢；这些值反映当时网络和服务状态，不作为固定延迟承诺。点击链路没有模型、embedding 或 rerank 请求，也没有预设的一秒等待计时器；2.4 秒计时器控制的是高亮显示时长。

修复后，当文档 ID、PDF 指纹均与当前已打开文件一致时，先按快照滚动浏览并显示核验提示。每次点击仍重新检查权限和解析版本，通过后才画高亮，确认结果不再次滚动。版本变化、请求失败或过时的点击结果都不能画旧高亮；指纹不符直接拒绝，缺少指纹时先核验再定位。未增加来源版本缓存。

同一浏览器、同一合成引用的前后采样：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 点击到开始滚动 | 1,163.5 ms | 47.8 ms |
| 来源校验 HTTP 请求 | 1,099.2 ms | 1,096.7 ms |
| 点击到出现高亮 | 1,130.6 ms | 1,129.8 ms |

这里改善的是点击后开始浏览的响应时间；网络校验及其后的高亮仍有等待，PDF 平滑滚动动画也需要时间。
