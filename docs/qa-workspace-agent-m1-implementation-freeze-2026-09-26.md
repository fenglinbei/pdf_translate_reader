# 工作区 Agent M1：云端访问实现范围冻结

日期：2026-09-26。版本：`qa-workspace-m1-scope-v1`。状态：**实现范围与验收边界已冻结；业务实现尚未开始。**

基线为 M0 完成提交 `7930434fcc5335af86457ce12167a94a9f3c2bf1`。本文件承接[升级计划](qa-workspace-agent-upgrade-plan-2026-09-26.md)及 [M0 冻结契约](qa-workspace-agent-m0-contracts-2026-09-26.md)，将 M1 拆成可实施、可验证的工作包。M0 的 Schema、预算、固定样本和历史测量保持原样；本轮只保存 M1 范围，不开启功能、执行迁移或部署。

## 1. M1 的完成目标

让 Agent 按问题需要，**发现、筛选、统计、读取和关联当前账号的云端工作区资料，并把回答所用的记录或统计口径保存为可回看的来源**。

完成后应能处理这些组合任务：

| 用户任务 | 必须形成的行为 |
| --- | --- |
| “这个集合有多少篇未归档文章？两个标签都有的呢？” | 数据库按统一条件聚合，集合/标签关联去重，解释总数、分页数量和分组重叠；不逐篇读 PDF |
| “找出我关于门控机制的笔记，核对论文依据。” | 搜索云端批注 → 读取具体笔记 → 沿存储关系找到文档 → 阅读原文；笔记与原文分别标来源 |
| “比较我的译法和术语约定。” | 读取云端划词缓存和术语/翻译约定，注明版本和采纳证据；本机独有内容声明未覆盖 |
| “以前问过这个问题吗？原回答依据是什么？” | 搜索历史标题/消息、读相邻消息和来源；重新验权后回读指定原文版本，不执行旧提问 |
| “我最近打开了哪些文章？这篇为什么暂时读不了？” | 读取云端已记录的位置/最近打开和解析/产物状态；缺少完成时间、阅读时长或设备状态时如实说明 |
| “这个时间段有哪些已记录调用，用了多少 token？” | 查询当前账号日志的受限投影与去重聚合，未知 usage 单列；不把日志当完整费用账本 |

Agent 对用户资料仅有只读操作。服务端正常保存消息、来源快照和执行记录，属于问答持久化，不向模型开放修改、删除或移动资料的工具。

## 2. 全部资源范围

M1 接入 **12 个云端资源类型**，并桥接已有文档正文工具。下面列的是必须实现的范围，不是“从中选几个演示通过”即可完成。

| 资源 | M1 访问范围 | 实现时必须保留的事实边界 |
| --- | --- | --- |
| `document` | 书目、作者/年份/摘要、已采纳元数据、收藏/阅读状态/归档；筛选、读取、计数、关联 | 元数据和论文正文分开；待确认建议有独立标记；内容版本和元数据版本分开 |
| `collection` | 名称、父子层级、详情、成员、直接/含子集合统计 | 递归防环；一文多集合按文档身份去重 |
| `tag` | 标签搜索、详情、成员、ANY/ALL 过滤及统计 | 列表与统计使用完全相同的交并语义；各标签计数之和不一定等于总数 |
| `annotation` | 云端笔记、高亮、摘录及同条批注中的译文；搜索、按字段读取、统计、回文档 | 一个 pin 是一条批注；个人笔记和客户端摘录不自动成为服务器核验原文 |
| `translation` | 云端划词缓存原文/译文、语言和已存模型/提示信息；搜索、读取、统计、回文档 | 身份含文档与 cacheKey；本机自由翻译历史留在 M4 |
| `term` | 文档术语条目、译法和相关翻译约定；查询、读取、按条目计数 | 需要稳定条目身份或绑定父记录版本；遗留 `confidence=user` 不足以证明逐词人工采纳，缺证据标 `legacy_unknown` |
| `thread` | 已保存会话标题、既有元数据、内容命中、真实工具分页、统计、消息关联 | 关联文档来自已保存引用/输入关系，不从当前打开文章猜测；查询历史与管理会话分开，分组/归档等新管理能力在 M2 |
| `message` | 用户/助手消息、角色、成功/失败/取消状态、时间/模型等元数据、前后各 0–2 条及保存来源 | 同时校验线程和消息未删除；旧回答是历史模型输出，不是新的论文依据 |
| `reading_state` | 当前云端阅读状态、最近打开、已保存页/滚动/缩放；查询、读取、统计 | 不推导读完日期、累计时长或逐页轨迹；位置变化使用实际投影版本，不能借用只覆盖元数据的 revision |
| `preference` | 明确保存的源/目标语言及文档翻译风格、术语约定，按白名单读取 | 不转储完整 settings、不作资料数量统计；未存的 answerLanguage 不从 UI 语言猜测 |
| `availability` | 文档、MathPix、QA 准备/发布产物及必要索引状态的可观察投影 | 解析完成与原文产物可读分开；只查状态，不触发上传/新解析，也不声称了解设备同步全貌 |
| `usage` | 云端 QA 和翻译等已有日志的调用类型、状态、模型、时间、已知 token；受限详情及聚合 | 同一次模型调用与 answer-stream 汇总去重；缺日志/usage 不算零，排除诊断正文和凭据 |

`document_outline`、`search_document`、`read_document` 继续承担正文/表格与已发布版本阅读，沿用现有 `R/C` 原文回执；书目查询和统计不要求先有可读正文。

首期可执行位置是 `cloud`。`current_device` 返回明确不可用；请求 `combined` 时只声明云端覆盖，缺失设备的联合 total 为 unknown，不把云端数量冒称完整联合数。

## 3. 五个通用只读工具

沿用 `qa-workspace-access-v1`：

| 工具 | 实现出口 |
| --- | --- |
| `workspace_overview` | 按需返回资源种类、实际操作能力、可用性和覆盖；不默认全库精确统计 |
| `workspace_query` | 白名单过滤/排序，默认 10、最大 30 张卡片，preview 最多 300 UTF-16 单元；用 limit+1 和稳定 ID keyset 实现真实续页 |
| `workspace_read` | 按记录/版本读取必要字段或消息窗口，明确实际读取范围、截断及续读，登记记录来源 |
| `workspace_count` | 与 query 共用过滤定义，在数据库聚合 distinct 总数/分组，登记统计时间、口径和覆盖 |
| `workspace_related` | 沿保存的集合/标签/文档/批注/消息/来源关系导航；不凭共现推断论文之间的支持或引用关系 |

身份、run、句柄、游标和资源范围来自认证上下文。模型参数不接受 userId、SQL、表名、URL、文件路径或任意表达式；未知或当前能力不支持的过滤条件明确拒绝，不静默放宽结果。

M1 的历史适配器访问当前已存在的未删除会话集合；新分组/归档口径在 M2 schema 与管理行为落地后启用。未具备该能力时，显式分组/归档筛选返回 `RESOURCE_UNAVAILABLE`，不能将缺字段解释成“归档数量为零”。运行时公开的参数能力须反映这一子集，不能仅复制 M0 全量设计 Schema 后假装字段均已可用。

新增记录引用 `O…` 与已有云文档 `D…` 通过服务器注册桥接。同一运行的云文档 query/related 结果可直接进入原文工具；跨用户、跨 run、旧版本句柄和改变过滤条件的游标均拒绝。

## 4. 来源必须贯通到保存和历史展示

当前实现只处理 `R/C` 原文路线，最终答案保存 RPC 和前端引用渲染也主要面向论文来源。M1 必须同时完成以下各环节，不能只增加后端工具名：

1. **登记与验证：**`workspace_record` 的 `W…` 绑定具体记录、版本、已读字段/范围；`query_snapshot` 的 `Q…` 绑定规范化过滤、统计时间、覆盖和结果；来源 authority 由服务端赋予。
2. **回答与流式输出：**模型能引用 W/Q，验证器按类型检查实际来源；来源元数据在对应标记前到达前端。新来源共享预算，不能挤进旧 PDF 引用数组冒充原文。建议增加独立 `sources` 流式字段，保留旧 `citations`；旧客户端未协商新能力时继续旧协议，不静默发送其无法展示来源的 W/Q 答案。
3. **原子保存：**采用 M0 目标表 `user_qa_sources` / `user_qa_message_sources`；终态答案及其来源关系同一提交成功后才发 done。旧 `user_qa_citations`、老消息和 `citation-locator-v2` 保持兼容读取。
4. **刷新与历史：**来源卡从已保存的读取快照还原，重新查看时再验权；来源被改动时区分“当时读取”与“当前版本”，删除/撤权后显示不可访问，不替换成同名文件。
5. **原文回读：**历史消息来源若指定文档 revision，则按该版本授权打开；版本已不可用时明确说明，不能通过只打开最新版实现虚假的历史核验。新 run 重新登记引用，不沿用旧 C/R/W/Q 编号。同一 run 的同一文档在首次正文打开时固定版本，后续请求另一版本返回明确 `VERSION_CHANGED`，本阶段不扩成同一文档多版本同时阅读。旧 indexed_chunk/document_text 来源若无法恢复，也只报不可用，不伪造 artifact。
6. **界面：**论文来源沿现有 PDF 定位；笔记/译文/术语来源展开对应记录；历史消息定位其会话和消息；统计来源展开过滤口径、时间、覆盖和去重规则。无原生编辑页的记录提供只读详情，不显示失效的 PDF 跳转按钮。

`user_selection` 的来源类型继续预留，真实选文输入及附件保存属于 M3。M1 不新增问 AI 弹框、草稿交接或选文几何行为。

## 5. 代码与兼容迁移工作包

| 工作包 | 必须完成的变化 |
| --- | --- |
| 服务端资源注册/适配器 | 在现有 QA 模块边界内增加可读的注册表、参数验证、资源投影、查询/计数编译、关系导航、句柄/游标及预算；不 import 浏览器仓储执行 service-role 查询 |
| 受限 SQL/RPC | 复用已有表及可用索引，补 JSONB 批注/译文/术语的必要投影与索引；新服务 RPC 仅授予 service-role，显式绑定用户并检查关系两端，不能向客户端开放可伪填用户 ID 的入口 |
| 来源和消息版本 | 新来源表、关系表、RLS/约束、原子答案提交；消息语义 revision/hash 作为 M1/M2 共用基础，删改/重生/恢复使旧依赖失效；流式 token/诊断累加不制造内容 revision |
| 版本化资源读取 | 记录实际读取投影及父资源版本；术语、阅读位置等缺合适版本的资源按有效投影生成版本，不能仅用记录 ID 或不相关 updated_at 冒充不可变内容 |
| 运行协议与遥测 | 接入五工具、W/Q 来源与旧正文协议，显式版本/能力协商；按文档事实、个人记录、统计、混合、普通交流记录资料使用，不再仅用 returnedChars 判定是否“读了文档” |
| 前端来源投影 | 类型分派、流式标记、来源详情、历史 hydration、会话/消息定位、旧 PDF 引用兼容；保持已确认的工作区布局和过程默认折叠 |
| 验证和交付 | 单元/数据库/流式/浏览器验证、固定脱敏轨迹、SQL 计划、资源回归、版本说明及兼容回退指针 |

新增来源写入权和 authority 字段由服务端控制；同用户外键/父记录归属与 RLS 均需数据库验证，不能只靠模型提示。现有业务 payload 不批量改写为“已确认”或伪造历史版本。

按 `M1-A 注册/版本/来源基础 → M1-B 文库/集合/标签 → M1-C 批注/译文/术语 → M1-D 历史及辅助资源 → M1-E 完整来源 UI 与回归` 推进。各包逐步跑通端到端，**全部 12 类资源出口满足后**才标记 M1 代码完成；一个统计演示不代表整个 M1 完成。

## 6. 资源和验收出口

沿用 M0：主模型 12 次、工具 24 次、每批 4；2 活动 / 8 排队；最多 8 文档；单读 14,000、单 run 返回 96,000 UTF-16 单元；新非原文来源最多 64/run，最终 C/W/Q 引用总容量仍为 128。

扫描单次最多 128,000、单 run 最多 1,000,000 UTF-16 单元；应用层兜底最多扫描 2,000 条轻量记录，达到上限明确 partial；精确 SQL COUNT 不受 2,000 匹配条数截断。查询缓存最多 2 MiB/用户、16 MiB/进程、60 秒；按用户、版本、过滤与位置隔离，修改/撤权不得继续命中旧授权结果。

| 验收组 | 固定依据与完成要求 |
| --- | --- |
| 文库筛选/精确计数 | M0-02、04–06、37：31 活动、2 归档、2 删除；集合直接 10/递归去重 15；标签 ANY 18/ALL 7；统一 query/count 条件，分页不重复遗漏 |
| 可用性与权限 | M0-03、07、11、35：零结果与不可用分开，拒绝跨用户/旧句柄/同名串源/材料指令；缺设备范围不能声称云端与设备已完整联合覆盖 |
| 组合阅读与来源 | M0-08–10、34：笔记→原文、历史回答→原文、云端术语/译文；W-only、Q-only、C+W+Q 三类回答均可保存/重开；33 个合法引用接受、129 总引用或 65 个新增非原文来源拒绝；仅实际读到的范围可引用，刷新/重生不串来源 |
| 搜索与状态解释 | M0-12、36：中文/英文/双语改写分别记录召回；阅读现状不推导不存在的完成次数和时长 |
| 补齐矩阵缺口 | 为 preference 缺项、usage 去重/未知用量、availability 多阶段状态、术语遗留采纳、JSONB 版本、reading_state 更新补 M1 专项案例 |
| 持久化/界面/性能回归 | 旧原文引用、普通问答、慢 SSE/取消/保存失败、10 用户有限排队、缓存隔离/失效/淘汰、桌面/窄屏/键盘来源操作、翻译/文库回归 |

原 38 个案例中明确标记 M1 的是 15 个：02–12、34–37。M0-10 同时含当前设备译文；M1 单列云端子场景及设备未接入声明，不能把完整混合案例提前标为通过。其他跨阶段项也记录适用子场景；执行证据另存，不修改 M0 冻结 fixture 的 `not_executed` 历史状态。

完成代码后必须跑全量 CI、真实适配器与原子 RPC 的隔离数据库检查、浏览器来源流程，并按 M0 相同环境重测资源；合成模型性能和真实供应商结果分别记录。真实模型抽样先确定合成数据与小额预算；本轮范围冻结不产生模型调用。

## 7. 与后续里程碑和发布的边界

| 后续阶段 | 仍由该阶段完成 |

| M2 | 自动标题/标题 CAS、会话分组和归档管理、独立活动排序、管理列表 UI、持久草稿；共用 M1 的消息版本与历史读取基础 |
